## Дизайн

**Продуктова правда (аудиторія, позиціонування, докази, обмеження) — `PRODUCT.md`. Джерело правди для всього візуального — `DESIGN.md`** (токени, типографіка, компоненти, правила). Будь-який новий екран чи компонент спершу звіряємо з ним. Якщо рішення суперечить `DESIGN.md`, питаємо Lera й оновлюємо `DESIGN.md`, а не обходимо його.

- Творчий орієнтир: **«The Shared File»** — сайт як дизайн-файл, у якому працює Lera з командою: бенто сірих плиток на білому, кожен кейс починається з доказу (чорним) і показує живий продукт; зверху тихий шар Figma (квадратне синє виділення, курсори з ролями, «You», один коментар).
- Акцент **Mulberry Ink** — лише для доказів на сторінках кейсів і курсиву в інтро. Шрифти: Geist, курсив Newsreader для голосу й цитат, Geist Mono для розмірів Figma.
- Проєктуємо одразу в коді. Еталонний концепт: `docs/concept/bento/index.html` (живий: https://claude.ai/artifact/LM1eTvkZLvNwBRAQ4TcyBr).
- Попередній напрям «The Proof Sheet» (концепти, кіт, DESIGN.md) — в архіві `docs/concept/v1/` і `docs/concept/*.html`.
- Історія рішень і референси: `docs/references.md`. Машинний опис дизайн-системи для Impeccable: `.impeccable/design.json`.
- Для дизайн-рішень і перевірок використовуємо скіл Impeccable (critique, polish, audit тощо).
- **Російська й білоруська заборонені завжди**, зокрема в привітанні.

## Технічне

- Next.js (App Router) і TypeScript.
- Хостинг — Vercel (автодеплой з гілки `main`). GitHub Pages більше не використовуємо.
- Стилі: єдине джерело — `ui/kit.css` (імпортується в `app/layout.tsx`). Нових значень у компонентах не пишемо: лише класи кіта й змінні з його `:root`. Шрифти — через `next/font`, `app/globals.css` лише підміняє `--font-sans` / `--font-serif` / `--font-mono`.
- Новий кейс: файл `content/work/<slug>.mdx` (`export const meta` + текст з компонентами з `components/case/CaseBlocks.tsx`), зображення в `public/work/<slug>/`, рядок у `lib/cases.ts`, плитка в `content/site.ts` (доказ, рядок, живий продукт, форма плитки). Кожна плитка кейсу веде на власну сторінку; поки повного тексту немає, сторінка коротка й чесно каже, що кейс готується.
- Контент живе в репозиторії як MDX. Зображення з Notion переносимо в репозиторій.
- Аналітика — найпростіший варіант, Vercel Web Analytics.
- Репозиторій: https://github.com/LeraDryha/portfolio (публічний). Не комітимо приватних даних.

## Структура репозиторію

```
app/                    сторінки: layout, головна, work/[slug]/, not-found, icon
components/shell/       верхня панель, живі продукти (Vis) і курсори, іконки, тема
components/home/        головна: бенто, поведінка (фільтр, тема, копіювання, анімації), привітання
components/case/        блоки кейсу для MDX, поведінка сторінки кейсу
content/site.ts         плитки кейсів, More work, контакти, привітання
content/work/           кейси, по MDX-файлу на кейс
lib/cases.ts            сторінки кейсів, посилання з плитки, наступний кейс
mdx-components.tsx      як Markdown у кейсах мапиться на кіт
public/work/<slug>/     зображення кейсу
ui/kit.css              UI-кіт: токени в :root + класи компонентів (джерело стилів)
ui/kit.html             вітрина кіта
ui/inventory.md         інвентар компонентів
docs/references.md      візуальні референси: лише посилання й нотатки
docs/concept/           концепти: bento/ (поточний напрям), v1/ і *.html (архів «The Proof Sheet»)
DESIGN.md               дизайн-система (джерело правди для візуалу)
PRODUCT.md              продукт: для кого сайт, що доводить, які докази є
```

Без папки `src/`. Запуск локально: `npm run dev`; збірка: `npm run build`.

## Пов'язані проєкти

- **Storybook для GRG Design System** — живий: https://grg-design-system.vercel.app (репозиторій LeraDryha/grg-design-system, Vercel, автодеплой з `main`). Кейс GRG у портфоліо посилається на нього.
  - Стек: React 19, PrimeReact 10.9.9 без теми (поведінка, клавіатура, ARIA), вигляд — лише з токенів, згенерованих з Figma-змінних. Золота світла й темна теми; ціль — WCAG 2.2 AA.
  - Готово (жовтень 2026): Foundations (кольори, типографіка, відступи, радіуси, тіні, 362 Base icons); компоненти Button, Action Button, Link, Input з повними сторінками документації; частини Form Field та Inline Select. Sign-up приклад і Social Button відкладені до Modal.
  - Кожна сторінка компонента: статус і Figma-посилання, Playground, When to use, анатомія, типи / розміри / стани, доступність, мапа «властивість Figma → проп». Для кейсу це доказ системного зв'язку Figma ↔ код.
  - Не показуємо: white-label палітри, логотипи GRX Pay / GRX Exchange / Golden Ratio Exchange, display-шрифт Bounded.
