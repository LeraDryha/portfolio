For testing:

- In a grid view, larger cards let users scan key information from report previews and find the right report faster.
- Actions can sit right on the card, hide in a context menu, or both: frequent actions such as Edit or Export stay visible, less common ones go into the menu.

## Creating a report

When creating a new report, the user wants to visualise table data after applying filters, manage and customise tables and charts, and save and export reports.

- Instead of showing all metrics mixed together in one table, group them by context into separate charts: volumes (Ad Requests, Ad Opportunities, Impressions), money (Spent, eCPM) and percentages (Fill Rate by Ad Requests and by Ad Opportunities).
- Let users name a report right when they create it, so the list isn’t full of “New Report”.

<Figure src="/work/adtelligent/a02.jpg" width={1600} height={1075} alt="Creating a report, first version." caption="Creating a report, first version." />

- A side panel brings all table settings into one place: columns, metrics and filter pills, so users see and change every parameter at once.
- A plus next to each section title follows the pattern of most systems with complex configuration. Selected filters move to the top of the list, so applied parameters are easy to review.

<Figure src="/work/adtelligent/report.jpg" width={1600} height={1479} alt="Report with charts grouped by metric type and a settings side panel." caption="Charts grouped by metric type, settings in a side panel." />

For testing: adding metrics and options with a “Plus” button keeps unused elements hidden and the interface cleaner.
