## Where it started

The company already had a design system, a legacy one, and I was the only designer updating it. It had to serve several products at once: payments, a crypto exchange, internal admin panels and a marketing website with API references, each in a light and a dark theme.

## Foundations

Everything starts from tokens: colour, typography, spacing, corner radius and elevation. Components use them instead of raw values: fills, paddings and corners are bound to variables, and every label uses a text style. Switching the theme changes the whole product at once.

## Components

35 components, from buttons and inputs to tables, date pickers and navigation. Every component page follows the same structure: the full variant matrix, usage guidelines, and examples on real screens.

### One component in detail: the button

The button has 720 variants, driven by a few properties: type, size, state, destructive, icon only, and left or right icons.

### Specs for hand-off

Composite components are assembled from atomic parts, and the parts are measured, so developers don’t have to guess paddings and gaps.
